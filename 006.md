## Слайд 1

**Заголовок** -- что такое строка в Go

В Go `string` — это **немодифицируемая** последовательность байтов: внутри — указатель на байтовый массив + длина. Типа «символ» в Go нет — ближайший — `rune` (алиас `int32`, номер Unicode-символа, лекция 1).

Ключевые свойства:

- **Иммутабельность**: нельзя «изменить третью букву» — любое «изменение» — создание новой строки.
- `len(s)` — количество **байтов**, O(1).
- Индексация — по байту: `s[i]` возвращает `byte` (uint8), а не символ.
- Нулевое значение — `""`: пустая строка, не nil.

```go
package main

import "fmt"

func main() {
	s := "hello"

	fmt.Println(len(s))      // 5
	fmt.Println(s[0])        // 104 — байт 'h'
	fmt.Printf("%T\n", s[0]) // uint8

	// s[0] = 'H' — не скомпилируется: строка иммутабельна
	// единственный способ «изменить» — построить новую:
	s2 := "H" + s[1:]
	fmt.Println(s2) // Hello
}
```

```
5
104
uint8
Hello
```

Иммутабельность — не просто особенность: именно поэтому строки можно свободно передавать и делиться ими, и именно поэтому существуют `strings.Builder` (слайд 10) и бенчмарк на слайде 12.

## Слайд 2

**Заголовок** -- байты и rune

Строки в Go кодируются в UTF-8: один символ занимает от 1 до 4 байтов. Латиница — 1 байт, кириллица — 2 байта. Поэтому `len()` возвращает байты, а не символы:

```go
package main

import "fmt"

func main() {
	s := "Падме Амидала"

	fmt.Println(len(s)) // 25 байтов: 12 символов × 2 + 1 пробел

	for i, r := range s {
		fmt.Printf("%2d: %q\n", i, r)
	}
}
```

```
25
 0: 'П'
 2: 'а'
 4: 'д'
 6: 'м'
 8: 'е'
10: ' '
11: 'А'
13: 'м'
15: 'и'
17: 'д'
19: 'а'
21: 'л'
23: 'а'
```

`range` по строке идёт по **rune** (символам), а не по байтам — на кириллице индексы скачут по два.

Чтобы работать с символами, конвертируем в `[]rune`:

```go
rs := []rune("Падме Амидала")
fmt.Println(len(rs))        // 13 — количество символов
fmt.Println(string(rs[:4])) // Падм
```

**Подводный камень:** слайс строки по байтовому индексу может перерезать символ пополам:

```go
fmt.Printf("%q\n", s[:3]) // "П\xd0" — 'П' и половина 'а'

// правильный путь:
rs := []rune(s)
fmt.Println(string(rs[:3])) // Пад
```
## Слайд 3

**Заголовок** -- UTF-8 строки


При конвертации `string` в `[]rune` количество байт для чтения каждого символа определяется исключительно по битовому префиксу его *первого (стартового) байта*: 
- если байт начинается с `0` (диапазон `0x00`–`0x7F`) — это однобайтовый символ (ASCII);
- если с `110` (`0xC0`–`0xDF`) — считываются 2 байта;
- если с `1110` (`0xE0`–`0xEF`) — 3 байта;
- если с `11110` (`0xF0`–`0xF7`) — 4 байта.

Все последующие байты многобайтовой последовательности всегда имеют префикс `10` (`0x80`–`0xBF`) и являются только продолжением.

Поэтому алгоритм декодирования (например, внутри `utf8.DecodeRuneInString`) работает просто:
- анализирует первый байт;
- по его маске вычисляет общую длину символа;
- извлекает ровно это количество байт и преобразует их в один `rune` (Unicode code point);
- сдвигает указатель чтения на следующую позицию в строке.

## Слайд 4

**Заголовок** -- поиск и сравнение

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	name := "Падме Амидала"

	fmt.Println(strings.Contains(name, "Амидала"))            // true
	fmt.Println(strings.ContainsAny("hook-42", "0123456789")) // true — есть хоть одна цифра
	fmt.Println(strings.ContainsRune(name, 'д'))              // true

	fmt.Println(strings.HasPrefix("/wh/4f2c9a", "/wh/"))      // true
	fmt.Println(strings.HasSuffix("photo.jpg", ".jpg"))       // true

	fmt.Println(strings.EqualFold("Application/JSON", "application/json")) // true
	fmt.Println(strings.Compare("apple", "banana"))             // -1
}
```

```
true
true
true
true
true
true
-1
```

- `==` — обычное побайтовое сравнение; `strings.Compare` — лексикографический порядок, возвращает -1/0/1.
- `EqualFold` сравнивает **без учёта регистра** (с учётом Unicode) — для заголовков, протоколов, пользовательского ввода.
- Типичные применения в нашем проекте: проверка префикса пути веб-хука (`/wh/`), проверка содержимого поля перед сохранением.

## Слайд 5

**Заголовок** -- разбиение и склейка

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	line := "host=localhost port=5432 user=test"

	fmt.Println(strings.Split(line, " "))    // [host=localhost port=5432 user=test]
	fmt.Println(strings.Fields(line))        // то же, но подряд идущие пробелы игнорируются
	fmt.Println(strings.SplitN("a,b,c,d", ",", 2)) // [a b,c,d] — не больше двух элементов
	fmt.Println(strings.SplitAfter("a,b,c", ","))  // [a, b, c] — разделитель «остаётся» с предыдущим

	fmt.Println(strings.Split("a,,b", ",")) // [a  b] — пустые элементы сохраняются

	// Join — операция, обратная Split:
	names := []string{"Квай-Гон", "Оби-Ван", "Энакин Скайуокер", "Падме Амидала"}
	fmt.Println(strings.Join(names, "; "))
}
```

```
[host=localhost port=5432 user=test]
[host=localhost port=5432 user=test]
[a b,c,d]
[a, b, c]
[a  b]
Квай-Гон; Оби-Ван; Энакин Скайуокер; Падме Амидала
```

- `strings.Split` вы уже видели в лекции 4 при разборе `PATH`.
- Разница `Split` и `Fields`: `Split(" a  b ", " ")` → `["", "a", "", "b", ""]`, а `Fields(" a  b ")` → `["a", "b"]`.
- Мнемоника: `SplitN` — «не больше N раз», `SplitAfter` — «разделитель после».

## Слайд 6

**Заголовок** -- семья Trim

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	name := "   Падме Амидала  "
	fmt.Println(strings.TrimSpace(name)) // Падме Амидала

	url := "https://example.com/hook/123"
	fmt.Println(strings.TrimPrefix(url, "https://"))      // example.com/hook/123
	fmt.Println(strings.TrimSuffix("report.pdf", ".pdf")) // report

	token := "Bearer abc123"
	fmt.Println(strings.TrimPrefix(token, "Bearer ")) // abc123

	// грабли: Trim принимает НЕ префикс, а НАБОР символов!
	fmt.Println(strings.Trim("hellowrd", "helo")) // wrd — h, e, l, o срезаны с краёв
}
```

```
Падме Амидала
example.com/hook/123
report
abc123
wrd
```

| Функция | Что срезает |
|---|---|
| `TrimSpace` | пробельные (пробел, табы, переводы строк) с обоих концов |
| `Trim(s, cutset)` | символы из набора `cutset` с обоих концов |
| `TrimLeft` / `TrimRight` | то же, но только с одного конца |
| `TrimPrefix` / `TrimSuffix` | точный префикс / суффикс |

Типичный случай в нашем проекте — валидация пользовательского ввода перед сохранением: так мы сделаем в `AddHandler` (слайд 18).

## Слайд 7

**Заголовок** -- регистр и замена

```go
package main

import (
	"fmt"
	"strings"
	"unicode"
)

func main() {
	ct := "APPLICATION/JSON; CHARSET=UTF-8"
	fmt.Println(strings.ToLower(ct)) // application/json; charset=utf-8

	// strings.Title — deprecated: апкает только первый символ всей строки.
	// Для «нескольких слов» собираем сами:
	s := "квай-гон джоу"
	parts := strings.Fields(s)
	for i, p := range parts {
		r := []rune(p)
		r[0] = unicode.ToUpper(r[0])
		parts[i] = string(r)
	}
	fmt.Println(strings.Join(parts, " ")) // Квай-гон Джоу

	fmt.Println(strings.Replace("a-b-c", "-", "+", 1))  // a+b-c — только первое
	fmt.Println(strings.ReplaceAll("a-b-c", "-", "+"))  // a+b+c

	// Map — преобразование по каждому rune:
	fmt.Println(strings.Map(func(r rune) rune {
		if r != '@' {
			return '*'
		}
		return r
	}, "user@example.com")) // ****@***********
}
```

```
application/json; charset=utf-8
Квай-гон Джоу
a+b-c
a+b+c
****@***********
```

- `ToLower` / `ToUpper` — Unicode-aware: с кириллицей работают корректно (побайтовый регистр дал бы кракозябры — вспомните байты vs rune, слайд 2).
- `strings.Title` **deprecated** (Go 1.18): использовать не надо, в чужом коде попадётся.
- `Map` удобен для маскирования: пароли, токены, e-mail.

## Слайд 8

**Заголовок** -- остальное полезное

```go
package main

import (
	"fmt"
	"io"
	"strings"
)

func main() {
	s := "абв абв абв"

	fmt.Println(strings.Count(s, "абв"))             // 3
	fmt.Println(strings.Repeat("аб", 3))             // абабаб

	fmt.Println(strings.Index("hello world", "world")) // 6
	fmt.Println(strings.LastIndex("a-b-c-d", "b"))     // 2
	fmt.Println(strings.Index("abc", "z"))             // -1 — не найдено

	// строка как io.Reader:
	body, _ := io.ReadAll(strings.NewReader("тело запроса"))
	fmt.Println(string(body))
}
```

```
3
абабаб
6
2
-1
тело запроса
```

- `Count` — количество **неперекрывающихся** вхождений: `Count("aaaa", "aa") == 2`.
- `Index` / `LastIndex` — позиция или `-1`; есть варианты `IndexByte` / `LastIndexByte` — быстрее, когда ищем один конкретный символ.
- `NewReader` — передать строку туда, где ожидается `io.Reader` (чтение файла, тело HTTP-запроса).

## Слайд 9

**Заголовок** -- иммутабельность и аллокации

Строка иммутабельна, поэтому `s += x` означает: **выделить новый массив длиной `len(s)+len(x)` и скопировать туда обе строки**. Для малого числа конкатенаций это не страшно — компилятор даже схлопывает простую цепочку `+` (без промежуточных переменных) в одну аллокацию.

А вот в цикле каждая итерация копирует всю накопленную строку — стоимость растёт квадратично:

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	// простая цепочка — компилятор соберёт в одну аллокацию:
	host, port := "localhost", 5432
	fmt.Println("host=" + host + " port=" + strconv.Itoa(port))

	// а в цикле каждая итерация «копирует всё»:
	var s string
	for i := 0; i < 100; i++ {
		s += "part=" + strconv.Itoa(i) + ";" // копия всего накопленного
	}
	fmt.Println(len(s)) // 790

	// string([]byte) / []byte(string) — каждая конвертация — полная копия:
	b := []byte("Привет")
	s2 := string(b)  // копия
	b2 := []byte(s2) // ещё одна копия
	fmt.Println(s2, b2)
}
```

```
host=localhost port=5432
790
Привет [208 159 209 128 208 184 208 178 208 181 209 130]
```

Когда строку собирают из множества частей (в цикле, много элементов), нужна структура, в которую записи идут «на месте», без копирования «всего». В Go это `strings.Builder`.

## Слайд 10

**Заголовок** -- strings.Builder

`strings.Builder` — растущий буфер байтов для сборки строки.

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	var b strings.Builder
	b.Grow(128) // зарезервировать ёмкость, если известен примерный размер

	b.WriteString("host=")
	b.WriteString("localhost")
	b.WriteString(" port=5432 user=test")
	b.WriteString(" sslmode=disable")

	fmt.Println(b.String())
}
```

```
host=localhost port=5432 user=test sslmode=disable
```

- Методы: `WriteString(s)`, `WriteRune(r)`, `WriteByte(c)`, `Write(p []byte)` — все пишут **в буфер**, не создавая новых строк. `String()` возвращает результат.
- Буфер переиспользуется: `Reset()` — тем же Builder можно собирать следующую строку.
- Сравните с `makeDSL` в `conn.go`: там `fmt.Sprintf` — для фиксированной маленькой строки это читабельно и достаточно. Builder выигрывает в циклах.

Что использовать, когда:

| Ситуация | Что берём |
|---|---|
| Несколько конкатенаций, важна читабельность | `+` или `fmt.Sprintf` |
| Сборка в цикле, большая строка | `strings.Builder` |
| Работа с байтами, нужен `io.Writer` | `bytes.Buffer` (Builder — лёгкий «строчный» случай) |

## Слайд 11

**Заголовок** -- опасность strings.Builder 

`strings.Builder` может стать причиной скрытых утечек памяти: его внутренний буфер (`[]byte`) никогда не уменьшается автоматически — вызов `.Reset()` обнуляет только длину (`len`), но сохраняет максимальную достигнутую емкость (`cap`).

Если такой `Builder` хранится в долгоживущей структуре или переиспользуется через `sync.Pool`, он будет удерживать в памяти огромный массив байт даже при последующей сборке новых коротких строк.

Чтобы работать с ним безопасно:

- всегда передавайте его по указателю (в него встроен механизм `noCopy`);
- заранее выделяйте память через `.Grow(n)` для избежания лишних аллокаций;
- не храните его в глобальных пулах без строгой проверки `Capacity()` — пересоздавайте экземпляр, если емкость превышает разумный лимит;
- следите за тем, чтобы время жизни самого объекта `Builder` не превышало время жизни самой большой собираемой им строки, позволяя сборщику мусора своевременно освободить базовый массив.

## Слайд 12

**Заголовок** -- бенчмарк: замеряем сборку строк

Бенчмарки — помните лекцию 4 (`testing.B`, `b.N`, `go test -bench`). Замерим «сборку в цикле» со слайда 9: три реализации одной задачи — дописываем в строку 100 готовых частей.

```go
package main

import (
	"fmt"
	"strconv"
	"strings"
	"testing"
)

var parts []string

func init() {
	parts = make([]string, 100)
	for i := range parts {
		parts[i] = "part=" + strconv.Itoa(i) + ";"
	}
}

func buildPlus() string {
	var s string
	for _, p := range parts {
		s += p
	}
	return s
}

func buildSprintf() string {
	var s string
	for _, p := range parts {
		s = fmt.Sprintf("%s%s", s, p)
	}
	return s
}

func buildBuilder() string {
	var b strings.Builder
	b.Grow(len(parts) * 8)
	for _, p := range parts {
		b.WriteString(p)
	}
	return b.String()
}

func BenchmarkBuildPlus(b *testing.B) {
	for i := 0; i < b.N; i++ {
		buildPlus()
	}
}

func BenchmarkBuildSprintf(b *testing.B) {
	for i := 0; i < b.N; i++ {
		buildSprintf()
	}
}

func BenchmarkBuildBuilder(b *testing.B) {
	for i := 0; i < b.N; i++ {
		buildBuilder()
	}
}
```

```bash
go test -bench=. -benchmem
```

```

BenchmarkBuildSprintf-14    147789      8055 ns/op    44616 B/op     299 allocs/op
BenchmarkBuildBuilder-14   4324059      277 ns/op      896 B/op       1 allocs/op
PASS
```

- Builder примерно в **16 раз быстрее** и в **99 раз меньше аллокаций** (1 против 99/299) — ровно то, что на слайде 9 мы описали словами про «копию всей строки».
- Здесь `Sprintf` хуже даже `+`: `fmt` каждый раз упаковывает аргументы. Урок: не «Sprintf плохой», а «в цикле не пакуют».
- Числа на каждой машине будут свои — сравнивайте реализации между собой. Как читать вывод подробно и методология бенчмарков — лекция 12.

### conn/conn.go

```go
package conn

import (
	"database/sql"
	"fmt"

	"module01/config"

	_ "github.com/lib/pq"
)

func NewConn(cfg config.DB) (*sql.DB, error) {
	db, err := sql.Open("postgres", makeDSL(cfg))
	if err != nil {
		return nil, err
	}

	if err = db.Ping(); err != nil {
		return nil, err
	}

	return db, nil
}

func makeDSL(cfg config.DB) string {
	return fmt.Sprintf("host=%s port=%d user=%s password=%s sslmode='disable' database=%s",
		cfg.Host, cfg.Port, cfg.User, cfg.Password, cfg.DBName)
}

```
